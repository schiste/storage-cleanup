# Contributing

Report concrete bugs, missing storage surfaces, portability issues, and safer or more accurate procedures through the repository's issue tracker. Search existing issues first. Anyone with permission to create an issue may contribute; maintainer status is not required.

Use synthetic examples. Never post personal file paths, usernames, inventories, logs, credentials, conversation histories, or other private data. For a sensitive security issue, use the hosting platform's private vulnerability reporting if enabled, or contact the maintainers privately; do not disclose sensitive details in a public issue.

When proposing a change, identify the operating system and relevant versions, explain what changes and why, and include evidence, reproduction steps, and validation where practical. Do not assume a directory name or age alone makes its contents safe to delete. Keep inventory separate from deletion and preserve explicit user exclusions and authorization.

New operating-system support should provide clearly identified, platform-specific discovery and cleanup guidance; verify commands against that platform's current documentation and test without modifying real user data. Update the skill description only when the new platform is actually supported.

Validate the skill frontmatter and its relative references, and test meaningful behavior where feasible. Explain which platforms, agents, and scenarios were tested and which were not.
