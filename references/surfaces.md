# macOS storage surfaces and verification

Use this as a discovery map, not a deletion list. Paths are examples relative to the current user unless noted. Check availability, ownership, timestamps and actual usage on the machine.

## Applications and caches

- Compare application bundles under `/Applications`, `~/Applications`, `/System/Applications` and relevant nested folders. Some App Store iOS apps use a `WrappedBundle` symlink and have a bundle identifier different from the outer directory name. Installed CLI tools, services and apps elsewhere also matter.
- Look for attributable folders in `~/Library/Application Support`, `Caches`, `Containers`, `Group Containers`, `Application Scripts`, `HTTPStorages`, `WebKit`, `Logs` and shared `/Library/Application Support`. Group containers and vendor folders may be shared by installed apps. Empty script directories are not meaningful space savings. Avoid asserting all leftovers were found.
- Browser support directories may contain history, profiles or bookmarks; app containers can contain saves. Cache directories and updater downloads may be recreated while an app is running; installed applications' components can be necessary even if an old main app is absent. Check downloaded installers against their current use before removal.
- `~/Library/Caches`, `~/.cache` and per-user temporary locations can contain compiler caches, package downloads and browser automation binaries. `~/Library/Application Support` may also contain user data, live indexes or recovery archives. On macOS, `/private/var/folders/.../{C,T,X}` can include app caches and temporary files, but `X` may contain Chrome code-signing clones with active executables and APFS-shared blocks. Use `lsof` and do not assume nominal size equals reclaimable size. Preserve current work, tests and recent diagnostics according to user instructions.
- App version bundles, release/upgrade backups and logs have different purposes. A rollback bundle is not an ordinary cache; a backup can hold unique session restoration data. Show dates, size and the specific restoration risk, and preserve any backups the user chooses.

## macOS storage, backups and synchronized content

- Use System Settings > General > Storage as a complementary inventory, including Downloads, Messages attachments, media, Music Creation and other users. “System Data” is a broad, variable category, not a safe deletion target. Apple distinguishes physically free space from available space, which also includes purgeable storage. [Apple storage categories](https://support.apple.com/guide/mac-help/find-and-delete-files-on-your-mac-syspf5a64aa6/mac)
- Inspect local iPhone/iPad backups under `~/Library/Application Support/MobileSync/Backup`; identify the device, backup date and restoration value before proposing removal. Prefer Finder's Manage Backups to delete a selected backup. A newer or cloud backup is not automatically equivalent, particularly for encrypted data. [Apple backup management](https://support.apple.com/en-us/108809)
- Time Machine local snapshots are normally removed automatically when space is needed and are counted as available by macOS. They are recovery points, not ordinary cache. Do not disable backups or delete snapshots merely to improve the reported number; explain the recovery impact and use Apple's documented procedure only if specifically justified and authorized. [Apple local snapshots](https://support.apple.com/en-us/102154)
- A snapshot listing can also contain macOS software-update snapshots; identify their origin rather than labeling every listed snapshot as Time Machine. Preserve update snapshots and avoid treating them as routine cleanup candidates.
- For iCloud Drive, check sync status and whether offline access is required. Finder's Remove Download frees the local copy while retaining the cloud file; deleting or moving synced content can affect other devices or the cloud. Mail attachment removal for IMAP accounts may also delete the server copy. Obtain authorization appropriate to the actual effect. [Apple iCloud Drive](https://support.apple.com/en-euro/guide/mac-help/mchl1a02d711/27/mac/27), [Apple Mail](https://support.apple.com/en-gb/guide/mail/mlhlp1001/16.0/mac/27)

## Developer artifacts

- Inspect Xcode's `~/Library/Developer/Xcode/DerivedData`, `iOS DeviceSupport`, archives and `~/Library/Developer/CoreSimulator/Devices`, plus simulator runtimes. DerivedData is rebuilt; device-support files may be needed again for a physical device; archives may be release artifacts; simulator devices contain state and app data. A mounted runtime's apparent disk usage can be confused with actual backing storage. Inspect `xcrun simctl list devices`, `xcrun simctl runtime list` and tool help before using supported removal commands. Xcode tooling can launch first-run installation.
- Package and compiler caches such as npm, pnpm, pip, uv, Go, Rust `sccache` and Node compile caches may be removed if authorized, but ongoing builds can fail and content can immediately return. Browser automation downloads (Playwright/Puppeteer) may require redownloads. Do not remove whole installations merely because they are large.
- For Docker, inspect `docker system df -v`, stopped containers, images, build cache and volumes separately. `docker system prune` also removes stopped containers and unused networks; `-a` expands image removal, and `--volumes` includes anonymous volumes that may contain persistent data. Prefer targeted cleanup such as build cache when authorized; do not infer that an unused volume is disposable. [Docker prune reference](https://docs.docker.com/reference/cli/docker/system/prune/)
- An installed Docker CLI does not establish access to its daemon: contexts may point to another runtime or socket, and permission or connection failures make usage unknown. Report the failure without concluding the store is empty or changing socket permissions.
- For Homebrew, `brew cleanup --dry-run` previews old versions and cached downloads; targeted cleanup can limit scope. Check the current command options and retain versions required by active projects or rollback plans. [Homebrew manual](https://docs.brew.sh/Manpage)
- Development worktrees, generated test evidence, `.git` metadata and recovery archives can contain uncommitted changes or unique history. Git `rr-cache` contains remembered conflict resolutions, not just redundant bytes. Inspect status and active worktrees; use supported Git operations with appropriate care and avoid aggressive pruning while repositories or agents may be active.
- For multi-generation environments, inspect each installation's manifest and active pointers, plus leases and open handles. An unreferenced generation is a candidate, not proof of inactivity; preserve in-use and rollback generations unless their loss is authorized. Shared files and APFS cloning can make aggregate directory sizes overstate savings.
- Prefer package-manager cleanup for managed versions. A local dry run may need metadata or network access even with update checks disabled; report failures rather than claiming completion. Keep versions pinned by projects and the active version. Separate a service's currently open log from rotated logs.
- Before relocating an ignored directory, verify it contains no tracked or non-ignored files or nested repositories. Git can report a directory as ignored because its files match ignore rules; if the directory path itself does not match `git check-ignore`, check the contained file paths individually.

## Agent history and Codex-specific stores

- Agent conversation and tool traces may contain sensitive or irreplaceable work. Identify the product and its actual storage location before inspection; consult its current documentation through whatever trustworthy sources are available. Prefer supported history-management operations and do not assume archiving frees disk space.
- For OpenAI Codex specifically, `~/.codex/sessions` contains local session rollouts; `archived_sessions`, `history.jsonl` and SQLite files are distinct stores. Prefer supported per-thread operations, preserving relevant descendants; consult current official OpenAI documentation when advising on Codex behavior. Do not infer that `history.max_bytes` limits the entire session store.
- Diagnose space using file size, allocated blocks, dates and record-type/field-size aggregates without exposing conversation content. Large rollouts can contain repeated context, tool outputs and compaction records; sampling does not establish the composition of the entire store. A file's latest modification date does not establish how much was written today.
- Check SQLite free pages read-only before considering compaction; never assume the history database is disposable or delete live WAL/SHM files. If offloading data, verify a consistent backup and restoration procedure before removing originals.
- Agent and app analytics databases, logs and snapshots may contain usage history, conversations or recovery points. Identify schemas and dates read-only and explain what may be lost; do not label an old database obsolete merely because a newer one exists.
